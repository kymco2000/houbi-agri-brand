# Clippings 素材消化

以繁體中文執行並回報。任務是從原始素材建立長期可用的知識、來源定位與回查清單，並維持可續作的批次紀錄。

## 啟動與路由

- 使用者未指定其他 vault 時，使用 使用者自行指定的 Obsidian 路徑。先讀最新 `agents.md`、`handoff.md`、`00_主控台.md` 與 `99_系統與封存/01_系統與協作/素材消化追蹤.md`，依實際目錄核對目標。
- 新筆記依「任務領域 → 內容屬性 → 主題」路由；課程教材、教師講解、作業、考試及研究歸 `02_研究區`；契約、圖說、施工、監造、品質、採購與工程案例歸 `01_工作區`。
- 依內容用途分類，不能因標題出現工程術語就把課程例題歸工作區。混合內容保留單一原始來源，設定主要領域，建立互鏈的課程知識與實務應用衍生筆記。用途無法判定的衍生接收紀錄放 `00_收件匣與待分類/`。
- 既有 `Clippings/`、`05_Clippings/` 或專案原始資料視為只讀輸入。分類本身不授權搬動、刪除、覆寫或公開原檔。

## 批次處理

1. 讀取最近進度及新增素材。日批次預設處理約 3 個唯一來源，依土壤／基礎工程文字、其他 Markdown、字幕側檔、圖片 OCR、影片轉錄順序續作；使用者指定範圍時依其要求。
2. 以來源 URL／影片 ID 建立來源群組，以 SHA-256 確認完全相同檔案。同來源不同內容保留版本差異；TXT、SRT、VTT、JSON、TSV 為同一素材的不同表示，不重複計入唯一來源，也不因此刪檔。
3. 有對應 NotebookLM 筆記本時，先查既有來源，避免重複加入；依既有授權加入素材，確認 ready，再以本批 source IDs 限定查詢。私有素材的新上傳須有授權。無法連線時可整理本機可讀來源，明確記錄未使用 NotebookLM；不得把歷史處理寫成當次成功。
4. 按格式處理：影片／錄音建立逐字內容與可得的時間碼、關鍵畫面清單；有原影片及擷取工具時保存實際截圖與時間定位，否則標記待擷取。文章須讀正文後分類，只有標題或 URL 時只建接收索引。教材／PDF／圖片保留頁碼；OCR／ASR 僅用於定位與初稿。
5. 建立少量衍生知識點，使用 [筆記範本](assets/derived-note.md)。每點附原始路徑或 URL、頁碼／時間碼或可搜尋段落、整理日期、可信度與限制。無可靠位置時明示缺口，不虛構時間碼。
6. 工程數值、公式、圖表、規格、頻率、試驗條件與教師指示須回查原檔；未回查時列「待確認」，不作正式結論。公共工程的案件判定須回扣該案契約、現行圖說、核定文件及書面指示。
7. 發現可重複步驟、判斷規則、檢核表、模板、工具串接或固定輸出，標記技能／工作流程候選並提醒使用者；建立其他新技能或公開發布需有相應請求。

NotebookLM 查詢可用：「只依這些來源整理核心概念、可核查的來源定位、跨來源關係及回查缺口；列出公式、數值、圖表、單位、教師指示的辨識風險；無可靠時間碼須明示；不補外部知識。」

## 進度與驗收

- 分別記錄原始檔數、唯一來源數、接收／索引完成、知識初稿、原檔回查完成、待截圖／轉錄；完成索引不等於完成消化。剩餘量必須附盤點日期與範圍，不能把舊庫存數當即時全庫統計。
- 寫入前讀最新目標；遇同檔併發異動重新讀取並合併本批段落。讀回新筆記，核對必要来源定位、分類、連結及原始檔保留狀態，再更新追蹤及 `handoff.md`。
- 回報本批產出、分類、剩餘項目、來源回查缺口與候選流程。自動化通知遵循當次排程的通知規則；技能載入不代表已啟動背景排程。
